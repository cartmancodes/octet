# Octet on your phone, Phase 2: the mobile app — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** one Expo app for the iPhone 15 and the Android Gemini 10 that pairs with `octet hub` and,
for every live session:

- watches it: transcript, grouped tools, goal, NOW line and queue;
- answers approvals, with Allow behind biometrics;
- sends prompts, cancels and steers;
- changes mode and model (full access needs biometrics and a typed confirmation);
- resumes or starts sessions.

It must be **fast**: smooth scrolling of long transcripts while streaming, low battery and memory
use. It must look **like the Octet TUI**: the same crimson-on-charcoal palette and the same mascot.

**Architecture:**

- **Protocol and state are plain TypeScript with no React Native imports**, so they test fast in
  Jest and run under Node:
  - `apps/mobile/src/protocol.ts` (generated by Rust, never edited);
  - `src/client/` — WebSocket client: hello/pair, request correlation, reconnect,
    cursors/dedupe, batching;
  - `src/model/` — a transcript reducer that mirrors the TUI's grouping, and session state;
  - a zustand store with fine-grained selectors.
- **The UI is Expo Router screens over that store.**
  - The transcript is a `@shopify/flash-list` of memoised rows, with a small in-house Markdown
    renderer.
  - Theme tokens copy the TUI's exact colours, plus the design-review light tokens.
  - The mascot is generated from `docs/design/octet-agent-modes/*.svg` into lean `react-native-svg`
    paths.

**Tech stack:**

- **Core:** Expo SDK 57, React Native 0.87, TypeScript (strict, as pinned by the template),
  expo-router.
- **App libraries:** `@shopify/flash-list` 2, zustand 5, react-native-svg, expo-camera (QR),
  expo-local-authentication, expo-secure-store, expo-haptics.
- **Test and lint:** jest-expo, @testing-library/react-native, ESLint (eslint-config-expo).
- **Native modules:** installed with `npx expo install` so their versions match SDK 57.
- **Rust:** one task touches the protocol generator and the hub.

**Spec:** `docs/superpowers/specs/2026-10-13-mobile-remote-design.md` (§4 the mobile app, §2
protocol, §3 phone-side guards).

## Global constraints

- **The gates.**
  - **Rust:** `make rust-check`, cargo via `scripts/rust-env.sh`. Two known flaky tests may need
    one re-run: `remote_control_reports_a_ready_host_with_the_phone_command` and
    `a_silent_cli_is_gone_after_the_probe_gives_up`.
  - **App:** `make mobile-check`, which Task 2 adds. It runs `cd apps/mobile && npm ci &&
    npm run typecheck && npm run lint && npm test -- --ci`.
  - Commit only inside `if <gate>; then git commit …; fi`. A task touching both sides runs both
    gates.
- **TDD.** Pure TypeScript (client, model, markdown, theme, mascot generator) is tested first.
  Screens get React Native Testing Library tests for behaviour (what shows, what a tap sends), not
  snapshots.
- **TypeScript.** `strict` on, plus `noUncheckedIndexedAccess`. No `any`: use `unknown` and
  narrow. Wire types come only from `src/protocol.ts`.
- **Lint.** `eslint-config-expo` plus `react-hooks` rules; no disabled rules without a comment
  saying why.
- **Performance budgets** (verified in Task 11):
  - JS work per incoming frame is batched, at most one store commit per 50 ms while streaming.
  - Rows are memoised, and only the session on screen re-renders on its events.
  - The FlashList transcript keeps 60 fps on a 2,000-row session in the profiler.
  - Memory: at most 1,000 transcript entries per session in memory (older ones dropped; the Mac's
    journal is the record), 200 KB of text per entry.
  - No polling timers while the app is in the background.
- **Theme.**
  - Dark tokens equal the TUI's: BG `#161113`, PANEL `#1f171a`, FG `#eae0da`, MUTED `#ae979a`,
    EDGE `#58333d`, ACCENT `#d87c82`, AMBER `#e0b477`, SELECTED `#40242c`.
  - Light tokens come from the design review: BG `#faf6f5`, FG `#302329`, MUTED `#725960`, EDGE
    `#d6bcc4`, ACCENT `#943f53`, AMBER `#825510`. PANEL and SELECTED are derived in Task 2 and
    tested for contrast.
  - Mascot palette: K `#0e1014`, d `#82192f`, r `#c42b40`, o `#f56a4e`, c `#f6debf`. Amber is for
    warnings and permission decisions only.
  - The theme follows the system (`userInterfaceStyle: automatic`).
- **Security.**
  - The device token lives only in `expo-secure-store`.
  - Nothing is stored on the phone except the hub URL, device name, settings and per-session
    cursors. Transcripts are never persisted (spec §4).
  - Allow asks for biometrics by default; full access always asks, plus a typed confirmation.
  - Every string from the hub is rendered as text, never as HTML, links or code to run.
- **Dependencies.** Only those named in this plan, installed with `npx expo install` or `npm i -E`
  (exact versions) so `package-lock.json` pins them. The `apps/mobile/node_modules` directory is
  git-ignored.
- **Commits.** Stage by path. Never stage `output/` or `crates/octet-tui/src/tests/keys.rs`, the
  user's unrelated uncommitted test; don't reformat it either. Each message ends with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No outward changes.** Don't run `tailscale serve`, don't change Tailscale, Claude or Codex
  configuration, don't create Expo or Apple accounts, and don't run EAS builds. Native builds
  aren't possible on this Mac (no Xcode, Android SDK or Java); the app is verified by type-checks,
  tests, `npx expo export` for both platforms, and a contract test against the real Rust hub.
- **Rulings recorded up front.**
  1. Markdown is an in-house renderer for a subset: paragraphs, headings, bold, italic, inline
     code, fenced code, bullet and numbered lists, block quotes, and links rendered as plain text.
     No library: performance and a small attack surface.
  2. The mascot is generated at build time from the SVGs by `apps/mobile/scripts/mascot.mjs`,
     which strips C2PA metadata and merges each colour into one path. The output
     (`src/mascot/poses.ts`) is checked in, and a test regenerates and compares it.
  3. Bundle and package id: `dev.octet.mobile`; app name "Octet"; URL scheme `octet`. A
     placeholder EAS `projectId` is left out until Phase 3.
  4. The device name defaults to the platform ("iPhone" or "Android phone"), and the user can
     edit it at pairing. No device-info dependency.
  5. The app never sends `Tailscale-User-Login`. `tailscale serve` adds it. The contract test sets
     it, the way a test client would.
  6. Workspaces offered for "New session" are the union of the live sessions' and the recent
     sessions' workspaces. The hub refuses anything outside its allow-list, and the app shows the
     refusal.

## Review focus

1. **Reconnect storms.** Wi-Fi to cellular while streaming, the app backgrounded and resumed, the
   hub restarted, `subscribed{from:"start"}` (a reset).
   - No duplicate or missing transcript rows.
   - The UI stays responsive.
   - The reconnect timer stops while the app is in the background.
   - Test: Task 3 `reconnects_resume_from_cursors_without_duplicates`; Task 4
     `a_reset_replaces_the_transcript`.
2. **A huge tool output or reply streaming in.** A 5 MB journal or a 200 KB text record must not
   freeze the JS thread. Bounded entries; batched commits. Test: Task 4
   `huge_records_are_clipped_and_batched`; Task 11 profiler budget.
3. **An approval arriving while the user is typing, or two approvals at once.** The sheet queues
   them; answering one shows the next; an approval closed elsewhere disappears; Allow can't be hit
   within 400 ms. Test: Task 8 `approvals_queue_and_close_elsewhere`.
4. **Hostile or garbage frames from a compromised hub or MITM.** Unknown types, huge strings,
   control characters, markdown with links or code. Never crash, never run anything; text only.
   Test: Task 3 `garbage_frames_are_ignored`; Task 7 `markdown_is_inert`.
5. **Unpaired, revoked or expired states.** `refused{code:"unpaired"|"revoked"}` sends the user
   to Pair and clears the token. A network drop never does. Test: Task 5 `revoked_unpairs`.

### Task 3: The hub client (`src/client/`)

**Files:**

- Create: `apps/mobile/src/client/{HubClient.ts, cursors.ts, backoff.ts, link.ts}` and tests
  beside them.

**Interfaces:**

```ts
export type HubState = "connecting" | "authenticating" | "ready" | "offline" | "unpaired";
export interface Socket { send(text: string): void; close(): void; onmessage?: (text: string) => void; onopen?: () => void; onclose?: (code: number) => void; }
export type SocketFactory = (url: string) => Socket;   // RN: wraps global WebSocket; tests: a fake
export class HubClient {
  constructor(opts: { url: string; token: string | null; factory: SocketFactory; now?: () => number; schedule?: (fn: () => void, ms: number) => () => void });
  pair(secret: string, name: string, platform: string): Promise<{ token: string; device: string }>;
  start(): void; stop(): void;                       // stop = background: closes, no timers
  request<K extends FromPhone["type"]>(cmd: Omit<Extract<FromPhone, {type: K}>, "v" | "req">): Promise<Ack>; // rejects with Refusal{code, reason}
  subscribe(session: string): void; unsubscribe(session: string): void;
  onBatch(fn: (frames: ToPhone[]) => void): () => void;   // ≤ one call per 50 ms
  onState(fn: (s: HubState) => void): () => void;
}
export class Refusal extends Error { code: RefusalCode | "timeout" | "offline"; }
export function parsePairLink(text: string): { url: string; secret: string } | null; // https://host/#pair=<hex> → wss://host/
```

- [ ] **Step 1: Failing tests** (fake socket and fake clock):
  - `hello_then_ready`;

  - `requests_resolve_on_ack_and_reject_on_refused_with_code`;

  - `reconnects_with_jittered_backoff_and_stops_in_background`;
  - `reconnects_resume_from_cursors_without_duplicates`: the cursor per session is the last

**Files:**

**Interfaces:**

```ts
export type Entry =
  | { kind: "user"; key: string; text: string }
  | { kind: "reply"; key: string; text: string; done: boolean }
  | { kind: "tools"; key: string; calls: ToolCall[]; over: boolean }
  | { kind: "note" | "error"; key: string; text: string };
export interface Transcript { entries: Entry[]; bytes: number }
export function apply(t: Transcript, ev: KnownJournalEvent): Transcript; // pure, structural sharing
export function summary(calls: ToolCall[]): string;                      // "Read 3 files · Ran 1 command"
export function label(name: string): string;                            // commandExecution → Bash, fileChange → Edit, mcpToolCall → MCP
```

- [ ] **Step 1: Failing tests.** Port the TUI's rules exactly (see `crates/octet-tui/src/view/transcript.rs`
  and `app.rs`):
  - **Grouping and pairing:**
    - consecutive tool events form one entry;
    - an end pairs with its id within this turn's tools entries, newest first;
    - an empty id never pairs;
    - a tools entry closes past 64 KiB;
    - turn end (`finished` or `stopped`) marks the running calls `over` (shown "· stopped").
  - **Summary words** (copy the Rust tests):
    - "Read N files", "Edited N files", "Wrote N files", "Ran N commands", "Searched N times",
      "{name} ×N";
    - singular forms;
    - Edit/MultiEdit/NotebookEdit/fileChange counted together;
    - Grep and Glob counted together.
  - **Failed calls:** the last 8 detail lines plus "+N more lines".
  - **Streaming:** text events append to the open reply; `finished` closes it.
  - `huge_records_are_clipped_and_batched`: at most 200 KB per entry, at most 1,000 entries per
    session, oldest dropped; the byte count stays exact.
  - `a_reset_replaces_the_transcript`.
  - **Store:** an event for session A doesn't change session B's object identity (selector
    stability); a sessions frame updates the list; `state` and `catalog` are stored per session.
- [ ] **Step 2.** Implement.
  - **The reducer** returns new objects only along the changed path.
  - **The store** (zustand):
    - `sessions: SessionInfo[]`;
    - `bySession: Record<id, {transcript, state, catalog, approvals}>`;
    - `hub: HubState`;
    - actions wired to the `HubClient`'s `onBatch` and `onState`;
    - hooks `useSession(id)` and `useSessions()` with shallow selectors.
  - **Approvals per session** come from the `state` frame plus journal `approval` and
    `approval_closed`.
